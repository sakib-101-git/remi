# Execution evidence

Everything in this folder is generated by scripts in this repository from real runs of the sandbox. Nothing is hand-edited. All money is fictional sandbox money, and all providers, banks and universities are fictional.

| File | What it shows | Produced by |
|---|---|---|
| `eval_report.md` | Pass/fail of the 13 golden scenarios (S1–S13) on the deterministic agent (`mock`), on a free real model (`gemini`, live) and on the recorded replay cache (`gemini-replay`): checks passed, provider that answered each turn, latency | `evals/run_evals.py` |
| `eval_results.json` | The same results in machine-readable form, including every individual check and its detail | `evals/run_evals.py` |
| `sandbox_logs/S<n>_<provider>.jsonl` | Per-scenario operation log: each user message, the agent's reply, the tools it called, the cards shown, action tiers/statuses/risk scores, confirmations and receipts, followed by the workspace's full hash-chained audit trail | `evals/run_evals.py` |
| `audit_export.json` | Audit log of one sandbox session (S1 paid end to end, S7 fraudulent invoice blocked, S10 and S12 refused), exported via `GET /api/audit/export` with its chain verification, plus a **tamper test**: one row is edited afterwards and verification fails at that row | `scripts/export_audit.py` |
| `playwright_results.json` | Browser end-to-end test of S1 through the real UI (chat → quotes → confirmation card → executed → receipt → settled → audit chain verified) | `cd frontend && npx playwright test` |
| `live_smoke_test.json` | The same S1 browser test run against the **live deployment** | `E2E_BASE_URL=<live url> E2E_REPORT=../evidence/live_smoke_test.json npx playwright test` |
| `pytest_summary.txt` | Output of the backend unit/API test suite | `cd backend && .venv/bin/python -m pytest` |
| `screenshots/` | Every screen and key chat card of the redesigned app at 1440×900 (`01_landing` … `17_styleguide`) and on a 390×844 phone (`m01_landing` … `m06_chat`), captured automatically from a running app driven through S1, S6, S7, S8 and S13 | `scripts/capture_screenshots.py` |

## How to read a sandbox log

Each line is one JSON object:

* `"step": "say"`: a user message, with `reply`, `tools` (tool names in call order), `cards`, `provider`/`model` (who answered; `guardrail` means a deterministic refusal before any LLM call), `cached` (served from the replay cache) and `actions` (proposed action id, kind, **tier**, status, risk score and policy reasons).
* `"step": "confirm"` / `"stepup"`: the human confirmation (with an idempotency key) or OTP step-up, with the resulting status and receipt.
* `"step": "tick"` / `"advance_hours"` / `"api"`: sandbox controls and direct API calls (FX rate tick, simulated time travel, settings changes).
* `"step": "audit"`: the workspace's audit entries, each with `seq`, `prev_hash` and `hash` (SHA-256 chain), actor, tool, tier, redacted inputs, decision and result.

## Reproduce

```bash
backend/.venv/bin/python evals/run_evals.py                                     # mock, offline, deterministic
backend/.venv/bin/python evals/run_evals.py --provider gemini --sleep 6 --cache record   # needs GEMINI_API_KEY
backend/.venv/bin/python evals/run_evals.py --provider gemini --cache replay    # replays the recorded answers
backend/.venv/bin/python scripts/export_audit.py
```

The sandbox clock is pinned to `2026-10-14T10:00:00Z` during evals so business-day arrival dates and risk-hour rules are reproducible.
